Design response · pass 02

The map was authored. The chrome was typed. This makes the chrome a system.

Pass 01 gave the game colour, glyphs and a typeface. Pass 02 gives it a component vocabulary: one button family, one panel anatomy, one number treatment, a type and spacing scale, and a menu that reads like a cover instead of a form. Every rule on this page resolves only to named tokens in tokens-ui.css (which extends pass 01's tokens.css), states are CSS rather than images, and the whole page re-themes live so you can judge light for yourself. The owner's note — "the buttons are clearly not planned out, they look pasted on" — is section 03.

02

Numbers

the thing the player actually watches

An incremental game is a game about a number going up, and ours were set in body text. The readout gives them a display treatment: tabular figures so digits never jitter as they tick, a thin space between thousands (never a comma), the unit dimmer than the value, and a fixed-width box so the panel does not resize when 300 becomes 3 000 000. Colour stays fixed to meaning — amber is money, green rises, red falls, politic is trust.

The player watches digits rise, so the default is the full grouped figure — the abbreviated 3.0M form exists only for spaces too narrow for seven digits (a drag label, a mobile HUD). One formatter, one flag.

03

Buttons

the top ask · one family, three weights, every state

The buttons read as pasted on because each was written on a different day with a different border and padding. This is one family. Three weights carry the whole game: the primary call to action (the bell), the standard menu button, and the inline control that lives inside a panel. Every weight resolves the same five states from the same tokens, so hover is one colour everywhere and disabled is a designed state rather than an opacity fade.

The matrix · weight down, state across

Live · hover, press and focus these

Disabled is designed, not dimmed

A disabled button keeps its border crisp and spends its right edge on the reason. "Unlocks in 1957" is information; a 45%-opacity ghost is just a bug the player has to squint at. Only a genuinely inert relic (a maxed upgrade the game is about to remove) uses the dim.

04

Panels

one anatomy for every floating surface

Every surface that floats over the map is the same object: a glass panel with an optional head, a body on the spacing scale, an optional divider and foot. The HUD money block, the station panel, the shop, the era panel and the feedback box stop being five hand-built boxes and become one component with content poured in. Head is a caption-caps title in muted; body rows are label-left, value-right; the whole thing sits in a corner and never covers the map.

05

Shop cards

where the player spends their reading time

Nineteen of these stack in the right rail, so the card carries most of the game's reading. It is the panel and button vocabulary in one object: an era-neutral icon, the name, the cost in amber, a description, and a pip row for level owned. The states are the whole design — affordable invites a click, unaffordable stays legible and names the shortfall, an era-locked card is a dashed promise with its year, and a trust project wears the politic keyline. None of them fades to 45% and hopes.

affordable green on hover, invites a click unaffordable cost dims to amber-dim, shortfall named locked dashed border, ghosted, year in politic project politic keyline, priced in trust maxed leaves the shop; the relic dims only if it lingers
06

Menu

the first thing anyone sees · a cover, not a form

The menu is the cover of the thing it opens, so it stops looking like a settings dialog and starts looking like the game: the wordmark and the portal mark large, a dark reveal of the map bleeding behind, the buttons left-aligned on the same axis as the era moments. One primary action, the rest standard, the disclaimer in micro at the foot. It is the pass-01 start-screen moment, now built from the pass-02 button family so the menu and the game speak the same language.

08

Back to the dev side

how to adopt it, and the light-theme call

Adoption order

Load tokens-ui.css after tokens.css, then port the component layer top to bottom: foundations, then buttons (the top ask), then swap each hand-built panel for the anatomy. Each step is independent and visible; nothing needs a big-bang rewrite.

The legacy alias block

index.html maps --bg, --panel, --ink onto the pass-01 names. Keep it: the component layer targets the --tb- names, so the alias can retire class by class as you port, not all at once.

Icons

Shop icons are the pass-01 upgrade grammar: 24 box, 2px stroke, currentColor, so a card colours its own icon by state with no extra files. New categories draw one shape by the section-07 rules in the design doc.

Light theme · my recommendation

Worth keeping, now that it costs nothing. Every component token is theme-independent, so light is purely the surface and aspect names re-pointed (in tokens-ui.css), which this whole page proves by re-theming with one attribute. I darkened the aspect colours for AA contrast on white and kept their meaning. Toggle the header to check it against every component at once.

One thing to confirm

Light is a genuine second theme to eyeball, not a designed atmosphere: the game's mood is the night city, and light mode is a bright room. If it is only a daylight-legibility aid, ship it as-is; if it is meant to feel authored, that is a separate pass and I would scope it.

Not in this pass

Sound, achievements, and the schematic diagram view, all still parked. Era moment cards and the ending were pass 01 and are unchanged; they already use this panel language.

Two files to take: tokens-ui.css (the new names) and this page's component layer, which lives in its <style> block behind the "this is the deliverable" banner. The pass-02 section of the design doc has the adoption notes and the full state table in prose.
