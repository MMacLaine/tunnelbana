# Tunnelbana v0.16 plan

## Purpose

v0.16 responds to player feedback about readability, discoverability, and
busy-map interaction. It should make the existing game easier to understand
and operate without changing the core economy, the campaign structure, or the
designed dark and light themes.

The release is deliberately split between work that is ready to implement and
one reported delivery problem that must be reproduced before a simulation fix
is made.

## Release boundaries

- This is version `0.16.0`.
- Existing Dark and Light themes remain the visual defaults.
- Settings are local preferences, not save-game state.
- Thorildsplan remains a hidden curiosity. It is not added as a playable
  station in this release.
- No deploy, GitHub push, maclaine.se update, or itch publication occurs until
  the owner explicitly requests the release.

## 1. Accessibility settings

### UI size

Add a saved Settings control with three choices:

- Standard
- Large
- Extra large

Standard must preserve the current presentation exactly. Larger choices must
scale the interface typography, controls, spacing where required for control
hit areas, and canvas labels/hit areas together. Scaling only CSS text would
leave map labels and crowded-station selection difficult on large displays.

The setting is for players whose display, viewing distance, or visual needs
make the intentionally compact default too small. It must not auto-scale based
on viewport width.

### Text contrast

Add a saved Settings control with two choices:

- Default
- High

Default preserves the current palette. High contrast raises the supporting
text colours used for muted and disabled copy without changing the semantic
colours for fares, warnings, trust, line identities, or the chosen theme.

This is intentionally a contrast choice rather than a freeform colour picker.
It gives players a reliable readable result and keeps the interface’s colour
meanings intact.

### Upgrade-card contrast

Independently of the optional high-contrast mode, correct the current
low-contrast treatment of locked and unavailable upgrade cards. A card that
cannot be bought must still state its name, cost or condition, and effect
clearly in a normally lit room. Disabled is information, not disappearance.

### Verification

- Preferences survive reload and malformed stored values fall back safely.
- Standard plus Default matches the current visual scale and palette.
- Large and Extra large keep panel controls usable at common desktop widths.
- Canvas labels and station/train hit targets scale with UI size.
- Dark and Light themes both retain legible unavailable upgrade cards.

## 2. Menu and Network clarity

### Achievements navigation

Add a compact Back button at the top-right of the Achievements view. It must
match the game’s existing button language and return to the main menu. Keep
the bottom Back button for players who finish scrolling the list.

### Network line rows

The current compact numbers are not self-explanatory. For example, `15 s 14`
means a service headway of 15 seconds and 14 active trains; it does not mean a
single compound metric.

Keep the Network rail compact while making each value understandable through
short visible wording and precise tooltips or accessible labels:

- service interval or headway
- active train count
- target train count and its `+` / `−` controls
- queued transfer state when present

Do not replace the rail with explanatory paragraphs. The line row should be
understandable at a glance and offer detail on hover or keyboard focus.

### Verification

- Screen-reader names identify each interactive train target control.
- Long line names still preserve reachable controls.
- The row remains usable at each UI-size setting.

## 3. Teaching at the moment of discovery

The existing How to play page is useful reference material but cannot be the
only explanation of newly unlocked mechanics.

### Charter and new-line coach

After a player charters or founds a line, show a one-time, contextual coach
that explains:

1. The charter created a line and supplied its initial train.
2. The line must be extended from its glowing end to begin serving more of the
   city.
3. The coloured stake and line end identify the intended continuation.

The coach must be brief, dismissible, and not repeat after the player has
successfully extended that line. It should guide the player on the map rather
than send them to a long manual.

### Help revisions

Tighten the relevant How to play sections so they agree with the coach and
explain, in particular:

- a charter is a new service, not a general map-building unlock
- how line ends, stakes, and interchanges relate
- what the Network train values and targets mean

## 4. Crowded-map selection and ambiguous builds

### Station versus train selection

At a busy interchange, trains currently win click priority over the station
beneath them. That makes the station panel hard to open at precisely the
stations players most need to manage.

Revise hit testing so:

- clicking a train’s visible body opens the train inspector
- clicking the station’s core or selection ring opens the station panel
- the two areas remain visibly distinguishable

This preserves the train inspector while restoring direct access to station
upgrades and interchange information.

### Choosing a line to build

One-click building should remain fast when there is only one legal extension.
It becomes misleading when multiple line ends can legally reach the clicked
stake.

Use an adaptive, non-modal choice:

- On hover, show the stake’s owning continuation in that line’s colour and
  name.
- When exactly one line can build there, clicking commits the build directly.
- When multiple lines can build there, the first click reveals a small picker
  beside the stake with each eligible line’s colour and name.
- Selecting an entry commits the build. Clicking away cancels it.

The picker appears only in the ambiguous case. It should make the choice
obvious without interrupting ordinary expansion with confirmation dialogs.

### Verification

- A busy interchange permits both station and train inspection.
- An unambiguous stake still builds in one click.
- An ambiguous stake never silently chooses a different line.
- Pointer, touch, keyboard focus, and map panning do not leave a stale picker
  or drag state behind.

## 5. Västerortsbanan rider report

A player reported that Västerortsbanan runs trains but never gains riders.
The current smoke suite proves that a two-line network delivers riders in
total, but it does not prove that the west line itself delivers riders.

### Investigation

1. Build the 1952 line through several west-corridor stations.
2. Run both services under deterministic dispatch.
3. Assert that Västerortsbanan’s own delivered and earned values become
   positive.
4. Exercise a route through the T-Centralen interchange.
5. Repeat after a save/hydrate round trip.

If the assertion passes, treat the report as a possible player-state or
interaction problem and improve the relevant explanation rather than changing
simulation logic. If it fails, isolate the routing, queue, or train-allocation
cause and add the reproducer as a permanent regression test before fixing it.

## 6. Music expansion

The current loop has two tracks, both credited to TAD’s CC0 OpenGameArt
compilation. Curate a small additional set from the same suitably licensed
source.

For every candidate:

- Verify the actual licence and permitted distribution before adding it.
- Record the artist, title, source, and licence in the game’s credits.
- Check loop behaviour, loudness, and tone against the existing two tracks.
- Use rotation that avoids immediately repeating a track.

Do not add a large catalogue or introduce a streaming dependency. The goal is
variety that retains the game’s quiet, relaxed atmosphere.

## 7. Thorildsplan decision

Thorildsplan is deliberately absent from the playable anchor list. A hidden
map curiosity at its real location appears once Fridhemsplan and Kristineberg
are built and explains the omission.

Keep it as that easter egg in v0.16. Adding it as a playable station would:

- remove an intentional discovery
- alter the campaign corridor sequence
- require save-safe handling for lines that already traverse the segment
- risk breaking numeric anchor references used throughout the simulation and
  saved games

The player report is still useful evidence that the curiosity is subtle. The
general contextual-help and map-clarity work in this release should make quiet
discoveries easier to notice without spelling them out.

## 8. Release and verification checklist

Before a release is requested:

1. Update `VERSION` in `src/sim.js` to `0.16.0`.
2. Update the `tb-version` meta tag and CSS cache versions in `index.html`.
3. Add an objective `0.16.0` entry to `updates.json`.
4. Run:

   ```sh
   node _dev/smoke.mjs
   node _dev/value-gate.mjs
   node _dev/probe-console.mjs
   ```

5. Confirm no console exceptions and manually check the new settings, map
   interactions, menus, and music rotation.
6. Commit without AI attribution trailers.

Publishing remains a separate owner decision. When authorised, follow the
documented game repository, maclaine.se, and itch release sequence.
